# 백엔드 /api/v1 prefix 규격화 및 리버스 프록시 2가지 모드 지원

## 목적

최종 운영 환경은 **같은 서버·같은 포트에서 리버스 프록시**를 통해 접근한다.
백엔드 REST·MCP 경로를 `/api/v1/*`로 규격화하면 외부 URL이 프론트 경유·백엔드 직행 모두
동일해지므로, 앱은 아래 두 모드를 **항상 동시에 호환**한다 (앱 설정 스위치 없음).
어느 모드로 라우팅할지는 **리버스 프록시 운영자(사용자)의 판단**이며, 이 저장소는 프록시를
구현하지 않고 안내 문서만 제공한다.

| 모드 | 프록시 라우팅 | 특징 |
|------|---------------|------|
| **A. 프론트 단일 업스트림** | `/` → `frontend:3000` | 기본값. 프론트 게이트웨이가 allowlist로 `/admin`·`/auth` 차단 |
| **B. 경로 분리 (Dependency-Track 방식)** | `/api/v1/` → `api:8000`, `/` → `frontend:3000` | 단계 하나 감소(MCP 스트리밍 단순). 차단은 프록시가 담당 |

## 현재 문제

- 백엔드 라우터에 공통 prefix가 없음 (`/entities`, `/auth`, `/admin/...`, `/mcp` …)
- 백엔드 `/entities`와 프론트 페이지 `/entities`가 **경로 충돌** → 경로 분리 라우팅 불가
- 에이전트 외부 URL(`/api/v1/*`)과 백엔드 실제 경로가 달라 게이트웨이가 경로를 변환해야 함
- 관리자 JWT 쿠키 `secure=False` 하드코딩 (`backend/app/api/auth.py:39`) — HTTPS 프록시 뒤에서 부적절

## URL 규격 (확정안)

외부 URL은 **두 모드 모두 동일**하다. 에이전트 쪽 변경은 없다(이미 `/api/v1/*` 사용 중).

| 외부 경로 | 처리 | 외부 노출 |
|-----------|------|-----------|
| `/` , `/admin/*`, `/bundle`, `/entities/*`, `/review`, `/login` | 프론트 페이지 | O |
| `/api/v1/{entities,relations,search,resolve,tags,context-bundle,ingest,export,validate-references,projects}/*` | 백엔드 REST (API Key) | O |
| `/api/v1/mcp/` | 백엔드 MCP streamable-http (API Key) | O |
| `/api/v1/auth/*`, `/api/v1/admin/*` | 백엔드 관리자 API (쿠키 세션) | **X** — 프론트 BFF 서버 내부 호출 전용 |
| `/api/v1/docs`, `/api/v1/openapi.json` | Swagger | X (운영), 필요 시 허용 |
| `/health` | 컨테이너 헬스체크 | X (내부 전용, prefix 밖 유지) |

규칙:
- 백엔드 모든 라우터·MCP 마운트는 `/api/v1` 아래. 예외는 `/health` 하나.
- 프론트는 `/api/` 아래에 페이지를 두지 않는다 (모드 B에서 프론트로 오지 않음).
- 하위 경로 배포(`example.com/registry/`)는 **범위 밖**. 루트 배포만 지원. 필요 시 별도 지침.

## 작업 단계

### Step 1 — 백엔드 prefix 적용
- [x] `backend/app/main.py`: 라우터를 `APIRouter(prefix="/api/v1")` 하나에 모아 `include_router` (각 라우터의 기존 prefix 유지)
- [x] MCP 마운트 `/mcp` → `/api/v1/mcp`
- [x] FastAPI `docs_url="/api/v1/docs"`, `openapi_url="/api/v1/openapi.json"`, `redoc_url=None`
- [x] `/health`는 루트 유지 (compose healthcheck 변경 없음)
- [x] 테스트: 테스트 클라이언트 `base_url`에 `/api/v1`을 반영하거나 경로 일괄 치환. `/health` 테스트 4건은 루트 경로 유지
- [x] 테스트 추가: `/entities`(prefix 없음) → 404, `/api/v1/mcp/` 인증 동작

### Step 2 — 프록시 환경 대응 (백엔드)
- [x] ~~쿠키 `secure` 환경변수~~ → 변경: 브라우저 쿠키는 **프론트 BFF가 설정**(`frontend/src/lib/actions/auth.ts`)하므로 프론트에서 `X-Forwarded-Proto: https`일 때 자동 `Secure` (설정값 불필요). 백엔드 쿠키는 내부 BFF 전용이라 유지
- [x] ~~uvicorn proxy-headers 설정~~ → 불필요: uvicorn 기본값(proxy_headers on, `FORWARDED_ALLOW_IPS` 환경변수 기본 127.0.0.1)으로 충분, 백엔드는 절대 URL을 만들지 않음
- [x] **MCP Host 검증**: 모드 B에서는 외부 도메인 Host 헤더가 그대로 들어옴 → `MCP_ALLOWED_HOSTS`에 공개 도메인 추가가 필요함을 문서화 (또는 프록시가 `Host: api:8000`으로 재작성)
- [ ] ~~`COOKIE_SECURE` 테스트~~ — 위 변경으로 해당 없음. Secure 자동 판단은 한 줄 비교라 e2e 미검증 (HTTPS 프록시 환경에서 수동 확인 필요)

### Step 3 — 프론트 경로 정리
- [x] `frontend/src/lib/api/server.ts`: 백엔드 호출 경로 `/api/v1` 반영 (관리자 `/auth`, `/admin` 포함)
- [x] `frontend/src/lib/api/gateway.ts`: 경로 변환 제거 — `/api/v1/x` → 백엔드 `/api/v1/x` 그대로 전달. allowlist·denylist 유지 (모드 A 보호)
- [x] `frontend/src/lib/api/mcp-gateway.ts`: 대상 `/mcp/` → `/api/v1/mcp/`
- [x] 프론트 테스트 경로 갱신
- [x] 에이전트 스킬 문서(`skill/llm-reference-registry/SKILL*.md`) — 백엔드 직접 URL도 `/api/v1` 반영

### Step 4 — 프록시 연동 문서 및 compose

> 리버스 프록시는 **이 저장소 범위 밖**(서버 관리자 영역)이다. nginx 설정 파일·컨테이너·
> compose 서비스를 소스에 추가하지 않는다. 예시는 **문서 내 코드 블록으로만** 둔다.

- [x] `docs/12-reverse-proxy.md` 신설 — 프록시 제품에 의존하지 않는 **요구사항** 먼저 기술
  - 라우팅 표 (모드 A / B), 외부 차단 경로 목록 (`/api/v1/auth/*`, `/api/v1/admin/*`, `/api/v1/docs`, `/api/v1/openapi.json`)
  - `X-Forwarded-Proto/For/Host` 전달, MCP 경로 응답 버퍼링 off·긴 read timeout (SSE)
  - 모드 B의 `MCP_ALLOWED_HOSTS` 설정 또는 Host 재작성
  - 참고 예시: nginx 코드 블록 (모드 A·B 각 1개). 다른 프록시(Caddy, Traefik 등)는 요구사항 표로 대체
- [x] `docker-compose.yml`: `api` 포트 → `127.0.0.1:8000` 루프백 바인딩 (완전 제거 시 호스트 설치 프록시가 경로 분리 불가). dev override는 `8000:8000` 유지
- [x] 검증은 프록시 없이 가능한 범위로: 프론트(3000) 경유 모드 A 동작 + 백엔드(8000) 직접 `/api/v1/*` 호출로 모드 B 경로 확인 (관리자 로그인, REST API Key 호출, MCP `initialize` → `tools/list`)

## 범위 밖

- 하위 경로(basePath / root_path) 배포
- 리버스 프록시 자체 (nginx 등 설정 파일·컨테이너) — 서버 관리자 영역, 문서 예시만 제공
- TLS 종료 설정 (프록시/서버 관리자 영역)
- 프론트 게이트웨이 삭제 (모드 A 지원을 위해 유지)
